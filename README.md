# RANEPARTY Pass - production release

Сервис именных QR-билетов для RANEPARTY: ручная выдача, Telegram-покупки с ручным подтверждением чека, QR-проверка обычной камерой телефона, роли сотрудников, журнал действий, PNG/PDF-билеты.

## Что входит

- `OWNER / ADMIN / CONTROLLER` по логину и паролю;
- ручная выдача билета из админки;
- Telegram-бот: ссылка на оплату -> имя и фамилия -> фото/скрин или PDF-чек -> решение администратора;
- PDF-чек читается как текст, а сканированный PDF дополнительно идёт через OCR;
- проверки суммы, точного/визуального дубля и распознанного номера операции - только подсказки администратору;
- билет создаётся только после ручного подтверждения;
- один билет = один проход;
- штатная камера телефона открывает QR-ссылку в браузере;
- гость без сессии видит билет, авторизованный сотрудник - экран проверки и кнопку `ПРОПУСТИТЬ`;
- атомарное погашение защищает от двойного прохода при одновременных запросах;
- PNG/PDF и напоминание заранее сохранить билет на телефон;
- CSRF для POST-действий, secure session-cookie, Trusted Host, security headers, rate limit входа;
- Caddy + автоматический HTTPS для `raneparty.ru`;
- PostgreSQL + Alembic, Redis для состояния Telegram-бота;
- технические логи в stdout и бизнес-аудит в БД;
- автотесты критического потока.

Встроенного веб-сканера нет. Никакого студенческого на входе сервис не требует.

## 1. DNS

У регистратора домена укажи A-запись:

```text
raneparty.ru -> IP_ТВОЕГО_VPS
```

Если IPv6 на VPS не настроен, не добавляй случайную `AAAA`-запись.

На VPS должны быть доступны входящие TCP 80 и 443. Caddy сам получает и обновляет TLS-сертификат.

## 2. Настройка `.env`

```bash
cp .env.example .env
nano .env
```

Обязательно замени:

```env
ENVIRONMENT=production
DOMAIN=raneparty.ru
PUBLIC_BASE_URL=https://raneparty.ru
ALLOWED_HOSTS=raneparty.ru

APP_SECRET=СЛУЧАЙНЫЙ_СЕКРЕТ_МИНИМУМ_32_СИМВОЛА
OWNER_USERNAME=owner
OWNER_PASSWORD=СЛОЖНЫЙ_ПАРОЛЬ
POSTGRES_PASSWORD=ОТДЕЛЬНЫЙ_СЛОЖНЫЙ_ПАРОЛЬ

PAYMENT_URL=https://РЕАЛЬНАЯ_ССЫЛКА_НА_СБОР
TELEGRAM_BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
TELEGRAM_ADMIN_IDS=123456789,987654321
```

Секреты удобно сгенерировать URL-safe строками:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
python3 -c "import secrets; print(secrets.token_urlsafe(24))"
```

Первую строку используй как `APP_SECRET`, вторую - как `POSTGRES_PASSWORD`.

Параметры мероприятия уже вынесены в `.env`:

```env
EVENT_NAME=RANEPARTY
EVENT_DATE=2026-10-31
EVENT_START=22:00
EVENT_AGE=17+
TICKET_PREFIX=RANE
EXPECTED_AMOUNT=500
```

## 3. Запуск

```bash
docker compose up -d --build
```

Проверка:

```bash
docker compose ps
docker compose logs --tail=100 app bot caddy
docker compose run --rm app python scripts/preflight.py
curl https://raneparty.ru/health
```

Ожидаемый ответ healthcheck:

```json
{"ok":true}
```

Админка:

```text
https://raneparty.ru
```

FastAPI, PostgreSQL и Redis наружу не публикуются. Публичны только 80/443 Caddy.

## 4. Telegram-покупка

Пользователь пишет `/start`. Бот показывает кнопку оплаты по `PAYMENT_URL` и инструкцию:

1. перейти по ссылке и оплатить указанную сумму;
2. вернуться в бот;
3. указать имя и фамилию для билета;
4. прислать чек как фото/скрин либо PDF-файл;
5. дождаться решения администратора.

Администратору приходит исходный файл, распознанные данные и кнопки `Выдать билет / Отклонить`.

OCR не подтверждает факт банковского перевода. Финальное решение всегда принимает администратор после просмотра исходного чека.

## 5. Проверка билета на входе

На каждом телефоне сотрудника:

1. один раз открыть `https://raneparty.ru`;
2. войти под `OWNER`, `ADMIN` или `CONTROLLER`;
3. дальше использовать обычную камеру телефона для QR.

QR ведёт на `/q/<случайный токен>`. Если браузер авторизован как сотрудник, сразу открывается служебная проверка. Простое открытие QR билет не гасит - нужен тап по `ПРОПУСТИТЬ`.

Если тот же QR откроет обычный гость, он увидит страницу своего билета.

## 6. Чеки

Поддерживаются:

- JPG/JPEG;
- PNG;
- WEBP;
- PDF до лимита из `.env`.

Проверяется фактическая сигнатура файла, а не только расширение. Есть ограничение размера и количества страниц. Для PDF сначала используется встроенный текст, а при необходимости первые страницы рендерятся для OCR.

Исходные чеки хранятся в Docker volume `receipt_data` и доступны только авторизованным `OWNER/ADMIN` через админку.

## 7. Логи

Есть два уровня.

### Технические логи

Web, bot и Caddy пишут служебные сообщения в stdout, а Docker ограничивает объём логов каждого контейнера: 10 MB, максимум 3 файла. HTTP access log у Uvicorn отключён, отдельный Caddy access log тоже не включён, чтобы URL с билетными токенами без необходимости не попадали в журналы.

```bash
docker compose logs -f app
docker compose logs -f bot
docker compose logs -f caddy
docker compose logs --since=30m app bot
```

### Бизнес-аудит

В БД отдельно сохраняются действия: создание/аннулирование/восстановление билета, проход, решение по покупке, создание/блокировка пользователя и т.д. Смотреть: `Журнал` в админке.

## 8. Тесты

Локально:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Проверяются, в частности:

- ручное создание билета;
- гостевая и служебная QR-страницы;
- погашение и повторный проход;
- CSRF;
- logout;
- security headers;
- отсутствие старого `/scanner`;
- PNG/PDF билета;
- PDF и изображения чеков;
- лимит страниц PDF;
- защита от повторного подтверждения покупки.

## 9. Обновление

Перед заменой версии сделай резервную копию БД:

```bash
docker compose exec -T db pg_dump -U raneparty raneparty > raneparty-backup.sql
```

Затем:

```bash
docker compose down
# заменить код, но сохранить свой .env
docker compose up -d --build
```

Не используй `docker compose down -v`, если нужны база и чеки. При старте `app` выполняет Alembic-миграции автоматически. `OWNER_USERNAME` и `OWNER_PASSWORD` синхронизируются с `.env`, поэтому перед production обязательно замени старый тестовый пароль.

## 10. Перед открытием продаж

Пройди `PRODUCTION_CHECKLIST.md`. Отдельно обязательно протестируй реальный банковский PDF-чек и реальное фото чека, потому что формат банковских документов различается.
